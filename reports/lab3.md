## 实现内容

## 问答题
### (1)实际情况是轮到 p1 执行吗？为什么？
**实际情况下，不会轮到 p1 执行，而是 p2 继续执行。**


**原因**
* 假设是 8 位无符号整数（范围 0~255）。

* 初始：p1_stride = 255，p2_stride = 250。此时 p2 较小，所以上一次调度了 p2。

* p2 执行一个时间片后，累加 pass = 10。250 + 10 = 260。

* 但是在 8 位无符号整数中，260 会溢出，变成 260 - 256 = 4。所以 p2_stride 变成了 4。

* 下一次调度时，比较 p1_stride (255) 和 p2_stride (4)。因为 4 < 255，所以系统会再次错误地选中 p2 执行，导致 p2 霸占 CPU。

### (2)不考虑溢出为什么最大差值 <= BigStride / 2？
现在有task1和task2,有max和min,此时max-min<=BigStride/2,不然的话，max-BigStride > min,此时在上一轮选择中应该选择min的，但是选择了max,矛盾，因此max-min一定小于等于BigStride/2

### (3)补全 partial_cmp
比较就是，看小的那个的顺时针 BigStride/2 环内有没有大者，有的话，他小，否则，另外的小
```rs
fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
        let a = self.0;
        let b = other.0;
        let half = BigStride/2;
        let diff = a.wrapping_sub(b);
        if diff < half {
            // a 离 b 顺时针不到半圈，a更小
            Some(Ordering::Less)
        } else {
            Some(Ordering::Greater)
        }
    }
```
