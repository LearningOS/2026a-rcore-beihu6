# lab2实验报告
## 1.请列举 SV39 页表页表项的组成，描述其中的标志位有何作用
`pte`有64位
* 63-54：reversed,保留位
* 53-10: 44位ppn,存放物理页号
* 9-8 : RSW
* 7-0 :八位标志位
    * V:仅当 V(Valid) 位为 1 时，页表项才是合法的；
    * R/W/X:分别控制索引到这个页表项的对应虚拟页面是否允许读/写/取指；
    * U 控制索引到这个页表项的对应虚拟页面是否在 CPU 处于 U 特权级的情况下是否被允许访问；
    * A(Accessed) 记录自从页表项上的这一位被清零之后，页表项的对应虚拟页面是否被访问过；
    * D(Dirty) 则记录自从页表项上的这一位被清零之后，页表项的对应虚拟页表是否被修改过。
    * G:优化 TLB 刷新，G=1代表全局映射，刷新TLB时不刷新
## 2.缺页
### (1)请问哪些异常可能是缺页导致的？
* Instruction Page Fault:取指令的时候，对应虚拟页无效 / 不在内存
* Load Page Fault : load 读内存，页面无效
* Store Page Fault : store 写内存，页面无效
### (2)发生缺页时，描述相关重要寄存器的值
- `scause`：标记异常类型；
- `stval`：触发缺页的虚拟地址 VA；
- `sepc`：触发缺页那条指令的 PC；缺页修复完成后`sret`直接重新执行这条指令，sepc 不需要 + 4；
- `sstatus`：SPP 位记录陷入前是用户态 U 还是内核态 S。
### (3)懒加载好处
* 节省物理内存，内存只在使用的时候被分配，不一直占用内存
* 内存申请返回快
### (4)处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？
一页4KB,有512个pte,可索引512页
* 10GB/4KB=2.5*(2^20);
* 三级页表： 2.5*(2^20) / 2^9 = 2.5 * (2^11);
* 二级页表： 2.5*(2^9)
大致占用`2.5*(2^11)*4KB=20MB`内存
### (5)请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。
当用户申请内存的时候，只给他的Memoryset添加上这段区域，注册MapArea,但是不分配页，也不映射。

当page falut的时候，查询MemorySet,看是否有效，如果已注册，就去分配物理页并映射。

## 3.单页表与双页表
### (1)在单页表情况下，如何更换页表？
RISC-V 中通过 `csrw satp, 页表根信息` 写入 satp 寄存器，设置 Sv39 模式、ASID 和新页表根的物理页号；之后执行 `sfence.vma` 指令刷新 TLB，完成页表切换。只需要在更换进程的时候更换页表即可，在trap时不需要切换页表
### (2)单页表情况下，如何控制用户态无法访问内核页面？
根据U标志位控制
### (3)单页表有何优势？（回答合理即可）
* 处理trap时不需要切换 satp、不需要刷新 TLB，陷入和返回的开销更小，性能更好；

* 内核可以直接使用用户虚拟地址，地址翻译处理简单。

### (4)双页表、单页表分别何时更换页表
* 双页表：U-S,S-U需要切换页表
* 单页表：仅在切换进程的时候切换页表
